# Automatic updates from GitHub Releases

Status: accepted

Amends the Local-only privacy positioning in [`PRODUCT.md`](../../PRODUCT.md) a third time, and settles the "Count requests to an update feed" option that [ADR 0078](0078-opt-in-anonymous-daily-usage-ping.md) deferred.

The App has no update check. A person learns about a new version only from the website or GitHub, and most never look. Bank sites change their pages without notice, and the fix for a broken source ships only as a new release, so an App that stays on an old version keeps failing after the fix exists.

**A released build checks GitHub for a newer release and offers it in the sidebar. It downloads the update, about 430 MB, only when the person asks or has turned on automatic downloads, and installs it when the person restarts or quits the App. Checking is on by default; downloading by itself is off by default.**

- **Where the request goes.** The App reads `https://github.com/WangWilly/OctopusBeak/releases/latest/download/update-feed-darwin-arm64.json` and, when the person asks, downloads the release's ZIP that it names from GitHub. Both requests go to GitHub, never to a host we operate. GitHub sees the connecting address and that this Mac runs OctopusBeak, as it does for any download. The requests carry no data, no identifier, no cookie, and no count, and nothing records them for us: update requests are never counted, and nothing about them reaches the usage statistics receiver.
- **Our own feed.** The feed is `{ "schema": 1, "version", "name", "pubDate", "url", "size", "sha256" }` for the release's ZIP. The main process parses it at the boundary and refuses anything malformed, including a `url` outside this repository's release downloads. It offers a release only when the feed's `x.y.z` is strictly newer than the running version, so the feed can never move an App backward. `scripts/update-feed.mjs` computes `size` and `sha256` from the built ZIP.
- **Checking and downloading happen in the App; Squirrel.Mac only installs.** Electron's `autoUpdater` on macOS (Squirrel.Mac) downloads as soon as a check finds an update and reports no progress, so it cannot offer a download the person chooses or show how far it has got. The main process therefore checks the feed with Node's `fetch` (15-second timeout, redirects followed) and streams the ZIP itself into `<userData>/updates/OctopusBeak-<version>.zip.partial`, reporting progress in whole percents. Only when the size and sha256 match the feed does it rename the file to `.zip`; a mismatch deletes it. At launch, the App deletes everything in that folder except verified ZIPs of versions newer than the running one, and a verified ZIP already there is not downloaded again.
- **The hand-off to Squirrel.Mac.** To install, the App serves the verified ZIP on `127.0.0.1`, on a random port behind a random path, in the format of Squirrel.Mac's default server type: the feed path answers 200 with `{"url": ".../update.zip"}`, and nothing else is served. It points `autoUpdater` at that feed and checks. Squirrel.Mac copies the ZIP, verifies that the new app is signed by the same Developer ID as the running one, and stages it for ShipIt; the App closes the server on `update-downloaded` or `error`. This is how electron-updater's MacUpdater installs. The sha256 check guards the transfer; Squirrel.Mac's signature check still decides whether the bundle installs.
- **The feed moves only forward.** The release workflow writes the feed for every release and uploads it with the installers; `releases/latest` resolves only to the newest published release that is not a prerelease, so a draft or a prerelease is never offered. A release cannot be withdrawn by publishing an older one: a version that has migrated the ledger schema cannot be opened by an older App, so a fix ships as a new version.
- **When it checks.** Once the automation runtime is ready after launch, then every 6 hours, and when the person turns checking on or selects Check now. A check that fails is silent and the next one tries again. Packaged test fixtures never check. A development build checks only a feed on `127.0.0.1` named by `OCTOPUSBEAK_UPDATE_FEED_FIXTURE`, so the flow can be driven without a release; it fetches the hand-off itself instead of calling Squirrel.Mac, and a packaged build ignores the variable.
- **The sidebar.** When a newer release is found, the bottom of the sidebar shows Download update with the version. While it downloads, the sidebar shows a progress bar with the percentage and megabytes; collapsed, a progress ring with the same text as its label. After the hand-off it shows Restart to update. A failed download, a checksum mismatch, or a refused hand-off offers Retry download. A download continues while runs are active.
- **Restart waits for runs.** A staged update installs when the App quits. The App never restarts by itself: it shows one notification once the update is ready ("新版 X 已下載，重新啟動即可更新"), and no notification when an update is merely available, because the sidebar shows that. Restart to update is disabled, and the request refused in the main process, while a run is active, because restarting would stop a sign-in the person may be in the middle of, or a collection that would then have to start over. Quitting the App normally also installs the update; quitting already stops active runs through the usual shutdown, so the ledger closes before the new version replaces the app.
- **Settings.** An Automatic updates section shows the current version, what the updater is doing, Check now, and two switches: 自動檢查更新 (`APP_UPDATES_ENABLED`, on by default) and 自動下載更新 (`APP_UPDATES_AUTO_DOWNLOAD`, off by default), which is disabled while checking is off. Turning checking off drops an update that is only available; a download already under way finishes and installs at quit, because the person asked for it.
- **Where it cannot update.** Squirrel.Mac cannot replace an app it cannot write, which includes an app opened straight from the DMG or from Downloads under App Translocation. A packaged App that `app.isInApplicationsFolder()` reports outside Applications therefore never checks, so it never downloads 430 MB it cannot install, and Settings asks the person to move OctopusBeak to Applications. A read-only-volume refusal from Squirrel.Mac leads to the same state. Other failures are logged as a code without the error message.

## Considered options

- **update.electronjs.org.** Rejected. It is a free service run by a third party that sits between the App and GitHub and sees every check. A static feed file in the release gives the same result with no service in between.
- **A third-party updater or SDK** (electron-updater, Sparkle). Rejected. electron-updater would give the same localhost hand-off, but brings a dependency and its own metadata format for a few hundred lines we can test directly; Sparkle needs a native framework and a separate signing key.
- **Squirrel.Mac's JSON feed, checked and downloaded by Squirrel.Mac.** Rejected. It downloads the whole ZIP the moment a check finds an update and emits no progress, so the App could neither wait for the person to ask nor show progress.
- **Download automatically by default.** Rejected. Each update is about 430 MB, a check runs every 6 hours, and a person on a metered or slow connection should choose when that happens. The sidebar makes the update hard to miss without spending the bandwidth first.
- **Notify only, and link to the download.** Rejected. A person still has to download about 430 MB, open the DMG, and replace the app by hand; most would not, and the fix for a broken source would still not reach them.
- **Checking off by default, like usage statistics.** Rejected. Usage statistics serve us; an update serves the person, and an App that cannot follow bank-site changes stops working. The check carries nothing about the person, and the switch is in Settings.
- **Restart automatically when idle.** Rejected. A person may be about to start a sync, and an App that restarts by itself looks broken.
- **Count requests to the feed.** Rejected. ADR 0078 counts consenting users; counting update checks would count everyone without asking.
- **Delta updates.** Not available: Squirrel.Mac downloads the whole ZIP.

## Consequences

- `PRODUCT.md`, `README.md`, and `README.en.md` name automatic updates as a request the App makes to GitHub, alongside usage statistics and Error reports.
- Every release must carry `update-feed-darwin-arm64.json`, listed in `SHA256SUMS.txt`, and the ZIP it names. A release without the feed leaves every installed App on its current version; a feed that names a missing ZIP, or a ZIP replaced after the feed was written, makes every download fail until the feed is written again.
- The ZIP is about 430 MB, each update downloads all of it, and a downloaded ZIP stays in `<userData>/updates` until the App runs that version or a newer one.
- Squirrel.Mac reads a feed only from `127.0.0.1`. No released App has an updater before this one, so the feed format needs no compatibility with an earlier one.
- A person who never quits the App keeps the old version until they restart or quit.
