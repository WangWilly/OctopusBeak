# Cross-process canonical writer lease

Status: accepted

Queue-mediated canonical writers and provider store opens now acquire a short-lived, path-keyed SQLite sidecar lease before their operation and release it after that operation settles. A provider run still gathers evidence and resolves relations outside its financial commit turn; its run handle may outlive many turns. This extends the in-process writer queue in [ADR 0025](./0025-canonical-financial-commit-execution.md) because Automation can run multiple providers in separate processes against one canonical ledger. SQLite's main-database write lock remains the final authority for direct synchronous writers and non-cooperating processes, and the schema lifecycle lease in [ADR 0017](./0017-canonical-schema-lifecycle.md) retains its separate physical-schema purpose.

The sidecar uses rollback-journal `BEGIN EXCLUSIVE`, a bounded, cancellable pre-transaction wait (ten minutes by default for a full multi-provider sync), and connection lifetime rather than a PID file, so process exit releases ownership. Waiting may be retried before the financial transaction begins; a failed transaction or commit is not automatically retried because its visibility may be uncertain. Contention diagnostics expose only timing, process ID, and a stable error category, never financial evidence or credentials. The in-process queue must await asynchronous operations before releasing its turn. Dashboard financial queries open the existing canonical store read-only so they do not request a lifecycle writer transaction while providers synchronize.

Increasing the main database busy timeout alone was rejected: it postpones the same failure if another process holds a transaction longer. Serializing whole provider runs was rejected because browser and human-assistance latency would block unrelated captures. A dedicated single-writer IPC process remains an alternative if sidecar coordination cannot cover future canonical writer entry points, but would add an application-wide process dependency and payload transport.
